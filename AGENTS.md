# Правила работы

- **Никогда не делать коммиты самостоятельно.** Просто писать готовый commit message в выводе. На русском. пример коммит мессаджа: 
```[Задача 92] Бэкапы по расписанию
- Добавлена вкладка Данные в раздел Администрирование. Отображает статистику использования данных.
- Добавлена возможность проводить бэкапы по расписанию.
- Добавлена возможность заливать бэкапы в облако.
- Изменена структура хранения файлов организаций: теперь документы хранятся в папках организаций, а не в общей папке.
- Добавлено отображение версии приложения.
- Добавлен скрипт для деплоя на проде.
- Добавлена инструкция по восстановлению данных из бэкапа
```
- **Правила описаний к коммитам.** Подробные правила для обычных коммитов, merge фича-веток в `dev` и релизных merge `dev` в `main`: [docs/commit-message-rules.md](docs/commit-message-rules.md).
- **Не удалять комментарии из кода.**
- **Минимальные изменения.** Не трогать ничего лишнего — только то, что нужно для задачи. Не удаляй комментарии. Не рефакторь просто так.
- **Задавать вопросы.** до тех пор, пока задача не станет полностью понятна.
- **Не начинать реализацию без явной команды.** Если просят решить задачу, но не говорят явно «реализуй» — нужен план, а не код.
- **Python запускать только в virtualenv проекта.** Перед запуском проверяй существующую среду и переиспользуй общую `.venv` в корне для всех Python-скриптов и тестов. Если среды нет, создай её; системный интерпретатор допустим только для команды создания virtualenv. Для запуска используй явный путь `.\.venv\Scripts\python.exe`, а не `python` или `py` из PATH. Зависимости описывай в корневом `requirements.txt` и устанавливай только через Python этой среды. Саму `.venv` исключай из Git. Встроенный Python STE Slicer используется самим приложением для плагина.
