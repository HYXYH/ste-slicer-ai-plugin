# Черновой план реализации ИИ-ассистента STE Slicer

Статус: черновик для обсуждения командой. Этапы и разделение ответственности ниже — предлагаемая основа для постановки задач.

## 1. Сценарии и границы проекта

### Базовый сценарий — решение основной задачи хакатона

Пользователь загружает модель и описывает назначение детали → ассистент делает первичный анализ → уточняет недостающие условия → предлагает план печати с объяснением → применяет согласованные изменения → запускает слайсинг → сохраняет 3MF и G-code.

Результат: настроенный проект и G-code, полученные через чатбот, с понятным объяснением выбора режима, материала, ориентации и параметров. Пользователь видит вызовы инструментов, их результаты и прогресс слайсинга.

При реализации учитываем требования задания:

- Python 3.5-совместимый код, PyQt5, формат плагина Cura 3.6 с `"api": 5`.
- Веб-интерфейс HTML/CSS/JS в системном браузере, связь с плагином через локальный HTTP-сервер.
- OpenAI-совместимый Chat Completions API с tool calling и передачей изображений; URL и ключ задаются в настройках, ключ не хранится в исходниках.
- MCP-сервер с `initialize`, `tools/list` и `tools/call` поверх API слайсера.
- Режимы `3D` (`classic`), `5D Spiral` (`cylindrical`) и `5D` (`cylindrical_full`). Основной профиль для тестов — Stereotech Hybrid 530 V5.2.4.
- Изменения сцены, настроек и запуск слайсинга выполняются из главного потока Qt.

### Сценарий калибровки — дополнительная ветка

Если подходящих проверенных данных недостаточно, ассистент объясняет неопределённость и предлагает калибровочную печать. Пользователь также может запросить её сам.

Предлагаемая последовательность:

1. Выбрать подходящий калибровочный образец и объяснить, что проверяется.
2. Подготовить проект и G-code для образца.
3. После физической печати получить ответы пользователя через опросник; при необходимости принять фото.
4. По результатам предложить корректировки с объяснением.
5. Применить согласованные изменения и повторить слайсинг.
6. Сохранить результат в базу знаний вместе с условиями печати, изменениями и оценкой пользователя.

Калибровка необязательна для прохождения базового сценария. Фото служит дополнительным источником информации; в первом прототипе диагностика опирается на опросник. Новая запись в базе — наблюдение с указанной областью применимости, а не универсальное правило.

Прямое управление принтером, автоматический запуск физической печати и контроль первого слоя предлагается оставить за пределами первого прототипа. Это отдельные расширения, требующие дополнительной интеграции.

## 2. План реализации базового сценария

### Этап 1. Загрузка модели и описание задачи

**В интерфейсе:**

- Поле сообщения, прикрепление STL/OBJ/3MF и изображений JPG/PNG.
- Список приложенных файлов и кнопка отправки.
- Отображение выбранного принтера и материала, если они уже заданы в слайсере.

**Нужно реализовать:**

- Каркас плагина, локальный HTTP-сервер и открытие веб-интерфейса.
- Приём файлов, проверку формата, сохранение и загрузку модели в сцену.
- Сессию диалога: сообщения, файлы, состояние задачи.
- Создание, переключение и переименование сессий с сохранением истории между перезапусками.
- Чтение текущего принтера, режима, материала и профиля.

Сцена STE Slicer общая для всех сессий. Переключение чата восстанавливает переписку
и вложения; модели и настройки автоматически не восстанавливаются. Операции импорта
привязаны к исходной сессии, даже если пользователь переключил чат.

**Результат:** модель загружена, описание задачи и исходные настройки доступны агенту.

### Этап 2. Первичный анализ

Агент сначала получает доступные данные через инструменты, затем формулирует вопросы.

| Источник | Что извлекаем |
| --- | --- |
| Описание пользователя | Назначение, нагрузки, условия эксплуатации, пожелания |
| Сцена слайсера | Габариты, масштаб, ориентация, количество объектов, положение относительно рабочей области |
| Настройки слайсера | Принтер, доступные режимы, материалы и профили |
| База знаний | Подходящие рекомендации, ограничения и недостающие условия выбора |

Для первого прототипа анализ геометрии ограничиваем перечисленными измерениями. Поиск тонких стенок, поверхностей под поддержку и оптимальной ориентации требует отдельных инструментов и задач разработки.

**Нужно реализовать:** инструменты чтения сцены и профилей, геометрических измерений и поиска рекомендаций; сбор результатов в состояние задачи.

**Результат:** известные факты, предварительные варианты печати и список существенных неизвестных.

### Этап 3. Уточнение недостающих условий

Вопросы задаются об условиях использования детали и доступных ресурсах. Параметры слайсера выводятся из ответов, профилей и базы знаний; отдельный вопрос для каждого параметра не нужен.

| Что выясняем при необходимости | Пример вопроса |
| --- | --- |
| Нагрузка | В каком направлении нагружается кронштейн? |
| Условия эксплуатации | Будет ли деталь нагреваться или находиться на улице? |
| Точность и сопряжения | Есть ли посадочные места, для которых важны размеры? |
| Приоритет | Что важнее: прочность, внешний вид или скорость изготовления? |
| Материал | PETG уже выбран или материал можно подобрать? |
| Ограничения | Допустимы поддержки и следы их удаления? |

**Логика вопросов:**

- Не спрашивать то, что уже известно.
- Спрашивать, когда ответ влияет на выбор режима, материала или существенных настроек.
- Объединять вопросы в один короткий блок.
- Предлагать варианты ответа и возможность написать свой.
- Если пользователь не знает — предлагать явное допущение; если без ответа нельзя продолжить — объяснять причину.

Ориентир — один блок уточнений. Повторный вопрос возникает, если ответ выявил новое ограничение или противоречие. Геометрию повторно анализируем при изменении модели, масштаба или других значимых исходных данных.

**Нужно реализовать:** состояние задачи с известными фактами, допущениями и обязательными неизвестными; правила уточнения из базы знаний; отображение вопросов и обработку ответов.

**Результат:** данных достаточно для составления плана, оставшиеся допущения явно зафиксированы.

### Этап 4. Предложение плана печати

Ассистент показывает структурированную карточку с коротким объяснением.

| Раздел карточки | Содержимое |
| --- | --- |
| Режим и материал | Выбранный режим, материал и исходный профиль |
| Положение модели | Предлагаемая ориентация и размещение |
| Изменения | Параметр, текущее значение, предлагаемое значение |
| Обоснование | Почему выбраны эти решения и на какие данные они опираются |
| Неопределённости | Допущения, непроверенные условия, предложение калибровки при необходимости |

Кнопки: **«Применить и рассчитать»** и **«Уточнить задачу»**.

**Нужно реализовать:**

- Машиночитаемый объект плана: настройки, преобразования моделей, объяснения и допущения.
- Проверку существования параметров, допустимости значений и доступности профилей.
- Отрисовку карточки из этого объекта.
- Связь плана с исходным состоянием сцены и настроек для проверки перед применением.

Текст объяснения и команды формируются из одного плана, чтобы интерфейс показывал именно те изменения, которые будут применены.

**Результат:** пользователь видит конкретные изменения и может согласовать их или уточнить задачу.

### Этап 5. Применение плана

После нажатия «Применить и рассчитать» плагин:

1. Проверяет, что исходная модель и настройки не изменились с момента составления плана. При изменениях обновляет план для согласования.
2. Меняет режим, профиль, материал, параметры и положение модели.
3. Считывает фактическое состояние и показывает результат.
4. При ошибке сообщает, что применилось, а что не удалось. Слайсинг запускается после разрешения ошибки.

**Нужно реализовать:** MCP-инструменты изменения состояния, выполнение операций в главном потоке Qt, проверку результата и журнал действий.

**Результат:** настроенная сцена соответствует согласованному плану.

### Этап 6. Слайсинг

После успешного применения плана слайсинг запускается автоматически.

**В интерфейсе:** состояние, прогресс, ошибка либо результат — расчётное время печати и расход материала.

**Нужно реализовать:**

- Запуск нужного бэкенда 3D/5D.
- Получение состояния и прогресса.
- Обработку ошибок.
- Чтение результатов расчёта.

Если слайсинг выявил проблему, ассистент объясняет её и предлагает исправленный план. Существенные изменения снова показываются пользователю перед применением.

**Результат:** слайсинг завершён, данные для экспорта доступны.

### Этап 7. Сохранение результата

**В интерфейсе:** кнопка «Сохранить результат», выбор папки и пути к созданным файлам.

**Нужно реализовать:**

- Сохранение текущего проекта в `project.3mf`.
- Экспорт результата слайсинга в `result.gcode`.
- Проверку успешной записи.
- Удобное отображение переписки, действий агента и результатов для скриншотов, требуемых при сдаче.

**Результат для сдачи по каждой модели:**

```text
results/<model_name>/
├── project.3mf
├── result.gcode
└── chat_*.png
```

## 3. Предлагаемое распределение работы

| Разработчик | Зона ответственности |
| --- | --- |
| Интеграция со слайсером | Каркас расширения STE Slicer, MCP-сервер и инструменты: загрузка модели, чтение состояния, геометрические измерения, применение плана, слайсинг и экспорт |
| Агент и знания | Подключение к LLM, цикл tool calling, извлечение требований, поиск рекомендаций, выбор вопросов, составление плана, объяснение ошибок и сценарий калибровки |
| Интерфейс и HTTP API | Локальный HTTP-сервер, чат, загрузка файлов, настройки подключения, вопросы, карточка плана, отображение вызовов инструментов, прогресс и сохранение результатов |

Специалист по материалам вместе с разработчиком агента определяет правила выбора, ограничения, вопросы и рекомендации для базы знаний.

## 4. Что согласовать до параллельной разработки

Определить четыре общих формата данных:

1. **Состояние задачи:** файлы и объекты сцены, исходные настройки, требования пользователя, известные факты, допущения и неизвестные.
2. **Уточняющий вопрос:** идентификатор, текст, варианты ответа, возможность свободного ввода и обязательность ответа.
3. **План изменений:** исходное состояние, выбранные профили и режим, изменения настроек и объектов, обоснования и неопределённости.
4. **Событие выполнения:** тип события, связь с задачей и операцией, данные сообщения, вызова инструмента, результата, прогресса или ошибки.

Также согласовать HTTP API и схемы MCP-инструментов: названия, аргументы, результаты и ошибки. Инструменты должны покрывать обязательный набор задания, включая работу с профилями, глобальными настройками и настройками экструдера, объектами сцены, слайсингом и экспортом.

Подготовить заглушки агента и инструментов с примерами этих данных, чтобы интерфейс, агент и интеграцию со слайсером можно было разрабатывать независимо.

## 5. Порядок сборки и проверки

1. **Общий каркас:** плагин открывает чат → сообщение доходит до Python → возвращается ответ → отображается вызов одного настоящего инструмента, например чтения настроек.
2. **Полный базовый сценарий на одной выданной модели:** от загрузки и уточнений до сохранённых 3MF и G-code, с отображением действий и объяснений.
3. **Покрытие требований и остальных моделей:** режимы 3D/5D, обязательные инструменты, изображения, профили и обработка ошибок.
4. **Сценарий калибровки и пополнение знаний:** после работающего базового сценария.
5. **Подготовка сдачи:** результаты по каждой модели, скриншоты переписки, заполненный README плагина с установкой и настройкой URL/ключа.

## 6. Вопросы для наполнения базы знаний

Начать со структурированных записей и поиска по условиям; необходимость векторного поиска определить по объёму и содержанию материалов. Реальные профили и допустимые настройки получать из слайсера.

Для каждой рекомендации специалист по материалам описывает:

- Для какого принтера, режима, материала и сопла она применима.
- Для какого назначения детали и условий эксплуатации подходит.
- Какой исходный профиль использовать и какие параметры изменить.
- Какие диапазоны допустимы и какие сочетания запрещены.
- Когда нужна калибровка и какой образец выбрать.
- Что спросить о результате печати и какие корректировки предложить по ответам.
- Чем рекомендация подтверждена и какие ограничения у неё есть.

При сохранении результатов калибровки фиксировать условия печати, исходные и итоговые настройки, наблюдения пользователя, оценку результата и источник записи.
