## Подтверждённые проверки

Команда из корня:

```powershell
$env:ASSISTANT_LIVE_HTTP = '1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check plugin/AIAssistant/web/app.js
node --check plugin/AIAssistant/web/analytics.js
git diff --check
```

Исходный прогон базового сценария: **40 тестов прошли, пропусков нет**, код возврата 0.
Набор выполнен на общей `.venv`, Python 3.14. Подробный вывод сохранён
в `.local-assistant-data/implementation-tests.log` и исключён из Git.

После добавления аналитики: **55 тестов прошли, пропусков нет**, код 0,
`.local-assistant-data/analytics-tests.log`. Добавлены 15 проверок агрегации,
периодов, отсутствующих/нулевых метрик, usage, ретраев, задержек, устаревания,
комплектов, текущих препятствий, ошибок backend, API, CSV и защиты доступа.
Проверена статистика применения/экспорта и отсутствие повторного выполнения
при повторе пользовательского HTTP-запроса. Синтаксис Python 3.5 и оба JS
проверены; проверка Python — синтаксическая, в `.venv` по-прежнему Python 3.14.

Первая проверка выявила гонку публикации терминального статуса и ошибки:
исправлена совместной публикацией под RLock хранилища. Новый тест повторного
экспорта сначала использовал внутренний метод, минуя HTTP-защиту повторов;
переведён на пользовательский API, затем полный набор прошёл.

В браузере проверены экран без метрик, заполненный дашборд на отдельных
синтетических данных, поиск, фильтр по препятствию, смена периода, кнопка CSV,
переход в чат и сохранение черновика. [Скриншот и правила подсчёта](analytics.md).
Тестовые данные не являются результатами по выданным моделям и не добавлены в results.

Проверены исходные сценарии P00, миграция и повреждённый JSON, числа и схемы,
источники и история требований, трёхзначная база знаний, ручные проверки,
реальный localhost MCP, токены, JSON-RPC, текст и изображения в запросах LLM,
несколько tool_calls и tool_call_id, 401, неверный/обрезанный JSON, повторы 429,
ограничение исправлений, отмена и поздний ответ, новое сообщение и изоляция
чатов, согласие, частичная ошибка, запрет устаревшего экспорта, повтор операций,
проверка ZIP и отказ от замены существующего файла. Отложенная Qt-команда,
отменённая до начала исполнения, не выполняется позже.

Синтаксис всего плагина проверяется существующим AST-тестом для Python 3.5.
JavaScript прошёл node --check. Browser QA в режиме разработки подтвердил
загрузку чата, сохранение сообщения и форму подключения.

Первоначальная проверочная установка в `.local-assistant-data/install-verification` выполнена
через `tools/install-plugin.ps1`. Скопированы 26 файлов, все SHA-256 совпали

Сетевой тест использует настоящий HTTP-сервер LLM с управляемыми ответами и
настоящий MCP транспорт. **FakeSlicer и тестовый writer не являются настоящими
STE Slicer или экспортёрами дистрибутива.** Эти тесты не подтверждают траекторию,
прочность детали, работу лицензии, API Qt внутри 7.10 или конечный комплект сдачи.

API сверены с открытыми исходниками:

- Uranium: commit `c4b662205dd75a66eb4fd75bc31c0756b4e11b1e`.

Это проверка исходников основной ветки. При первоначальном поиске установленный

## Оставшиеся ограничения

1. Предварительная проверка поддерживает текущий режим и материал. Неподтверждённая
   другая конфигурация блокирует план с TARGET_CONFIGURATION_UNKNOWN. Выберите
   её в STE Slicer и повторите анализ. Не выполняется скрытое переключение.
2. Проверенных инженерных рецептов нет. Семь описаний задач имеют статус observation.
   Критичные требования требуют ручной проверки именно соответствующего требования.
3. Действия создания/сохранения профиля и преобразования сверены с исходниками,
   но не выполнены в установленном STE Slicer. Новый профиль получает ID после
   создания; его дальнейший выбор требует повторного чтения каталога.
4. Backend и writers подключены, но настоящих project.3mf/result.gcode не получено.
   Нет API key организаторов и подтверждённой лицензии 5D. Все режимы требуют
   проверки на Stereotech Hybrid 530 V5.2.4.
5. Нет скриншотов реальных диалогов и комплектов по семи моделям. Пустые или
   тестовые файлы под видом результатов в results не добавлялись.

## Следующая проверка в приложении

Обновление после настоящего прогона: 75 тестов прошли, без пропусков.
Контекст перестал расти от полных старых чтений. Для Timeweb/Qwen ограничена
генерация, корректная первая карта не требует повторного запроса.
Ограниченная генерация вернула HTTP 200; карта отклонена сервером.
Подготовлена общая JSON Schema с точной диагностикой. Её работа через шлюз
и полный экспорт ещё не подтверждены.
Подробности и реальные метрики: [журнал проверки](native-verification-2026-10-24.md).

Закройте STE Slicer. Запустите `install-plugin.cmd`, затем откройте приложение.
Выберите принтер Stereotech Hybrid 530 V5.2.4 и откройте чат AI Assistant.
Введите Base URL, модель и ключ организаторов в форме подключения.

Сначала пройдите полный путь на одной выданной модели: загрузка, описание,
уточнения, проверка карты, согласие, применение, расчёт и сохранение.
Сравните реальные значения с карточкой. Проверьте предпросмотр, повторно
откройте 3MF в отдельной сцене. Затем проверьте все инструменты P09,
три режима, ошибки записи, ручное изменение сцены и оставшиеся модели.

Подробный чек-лист P01–P12 находится в разделе 17 плана. Существующие шесть
отметок pass P00 сохранены; новые отметки ручной приёмки не проставлялись.
Этапы P11 и подготовка конечных комплектов P12 остаются открытыми.
