# Интеллектуальная калибровка

Необязательный сценарий работает в текущем чате после подготовки итогового плана,
отдельно от «Готовности данных». Если меняются профиль или материал, оценка обновляется
после применения: эффективные значения прежнего профиля не выдаются за значения нового.

## Оценка

Восемь характеристик объединены в шесть групп: адгезия, экструзия, точность, ретракт,
охлаждение (мосты, нависания, мелкие элементы), межслойное сцепление. Учитываются
явные `checks` и отмеченные дефекты. Общее «дефектов нет» не подтверждает мосты
и прочность. Старые кубы без снимка настроек не переносятся на текущие условия.

Принтер, материал, сопло, экструдеры и режим должны совпадать точно. Сходство
параметров оценивается по ключам соответствующего риска. Другая геометрия получает
пониженный вес; идентичный STL не обязателен. Неизвестные условия и исключённые
наблюдения не используются. Исправление результата, дефектов или измерений
инвалидирует прежние отметки отдельных проверок.

Модель признака: `Beta(alpha0 + s, beta0 + f)`, где `s`, `f` — взвешенные успехи и
неудачи. Это приближение Beta-Binomial с дробными весами, не откалиброванный прогноз.
Отчёты одного расчёта и связанные исходные/повторные печати объединяются в зависимые
группы; вес группы не превышает единицы. Подтверждение исправления для переноса
отдельно требует двух независимых пар. Один исходный расчёт или повтор не удваивает подтверждение.

`U = P(дефекта) × P(обнаружения) × P(исправления) × потери − стоимость теста`.

Численный U требует достаточных независимых наблюдений каждого множителя: дефекты,
воспроизведение известной проблемы тестом без промежуточного исправления, оценённые
попытки исправления. Затраты вводит пользователь через `i` в общих условных единицах.
Расчёт относится к одному риску; коррелирующие риски не суммируются. Предложение
изменения не считается успешным исправлением.

При нехватке оснований U остаётся `null`. Холодный старт учитывает число непроверенных
характеристик, сложность из описания, размеры и габаритный объём основной модели,
реальные неудачи. Габаритный объём — эвристика потенциальных затрат, не объём пластика
или время печати. Для простой небольшой детали без замечаний тест не навязывается.
Если даже верхняя граница пользы ниже указанных затрат, предложение подавляется.
Пропуск сохраняется для тех же условий после перезапуска.

Prior, веса и пороги: `plugin/AIAssistant/calibration-policy.json`. Пользовательские
переопределения: одноимённый JSON рядом с `sessions.json` (обычно
`steslicer/7.10/ai_assistant`). Неверная политика отключает необязательную оценку
с объяснением, не блокируя план печати.

## Каталог и процесс

`models/calibration-catalog.json` содержит семь локальных STL, контрольные суммы,
габариты, проверки, исключения, измерения, режимы и относительный ранг стоимости.
Ранг используется для выбора, это не выдуманные минуты или граммы. Источник из
предоставленного архива сохранён. Скрипт `tools/import-calibration-models.py`
воспроизводит набор из `rec3d_calibration.zip`.

Для нескольких неопределённостей выбирается `ksr_fdmtest_v4.stl`, для конкретного
риска — малые тесты ретракта, мостов, нависаний, точности, мелких элементов или куб.
Температурные башни отключены. Автовыбор доступен только для планарного 3D:
применимость этих моделей к 5D не подтверждена. Мосты и нависания проверяются без
поддержек — это отдельное условие теста в согласуемом плане.

1. Сохранить основной проект и выбрать «Провести калибровку»: STL прикрепляется
   и импортируется прежним механизмом, новый чат не создаётся.
2. Подготовить план. Он явно перечисляет удаление других моделей из сцены.
   Только штатное согласование разрешает изменения и слайсинг. Экспорт — прежними инструментами.
3. После физической печати выбрать расчёт, заполнить доступные проверки, дефекты,
   измерения и фотографии. Неизвестное и непроверенное сохраняются отдельно.
4. Уточнить симптом по альтернативам справочника, проверить физические причины,
   согласовать изменение одного параметра и напечатать повтор.
5. Сохранить новый результат и эффект. При неудаче предлагаются откат с согласием
   и проверка другой причины.
6. Завершить или отменить. Наблюдения остаются в SQLite. Основная карта задачи
   восстанавливается как устаревшая; пользователь возвращает сохранённый проект и обновляет анализ.

Состояние — в существующем `sessions.json`, факты и эксперименты — в прежней SQLite.
После перезапуска планы требуют проверки сцены. Операции с неизвестным исходом
не выполняются автоматически повторно.

## Фотографии

Пользователь выбирает конкретные снимки и подтверждает отправку на показанные адрес
API и модель. Разрешение привязано к получателю: его смена требует нового согласия.
Только выбранные снимки отправляются как `image_url` с data URI, включая пошаговый
режим. База64 не сохраняется в истории. Фото дают гипотезы, не подтверждённые факты.

При явном отказе API поддерживать vision основной анализ повторяется без изображений
с предупреждением. Ошибка отдельного фотоанализа оставляет текстовую диагностику.
Тесты проверяют реальный HTTP payload на локальном тестовом провайдере; они не
подтверждают возможности конкретного внешнего LLM или физическое качество печати.
