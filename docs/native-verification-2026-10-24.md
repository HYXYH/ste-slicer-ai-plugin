## Проверка схемы карты после успешного ответа Timeweb

Ручной прогон 24.10.2026, 14:54–14:56 Asia/Yekaterinburg:
сессия `ddf37041d08648aeb78bb05e522f700d`, запуск `fc404c9e354746729f18b55a8dfd7c70`.
Получены три HTTP 200: 39 781 мс / 20 522 токена, 30 594 мс / 19 158 токенов,
36 485 мс / 21 284 токена. Во всех ответах reasoning_present=false.
Последние запросы использовали enable_thinking=false, max_completion_tokens=8192,
JSON Object. Ошибка анализа — INVALID_MODEL_OUTPUT; карты, плана и файлов нет.
В прочитанной конфигурации по-прежнему cylindrical_full (5D).

Точная причина отказа прежних карт не была сохранена и после завершения запуска
недоступна. Обнаружен пробел контракта: текстовый prompt описывал структуру, но
не передавал точную JSON Schema, которую проверяет сервер. JSON Object гарантирует
только синтаксис JSON. Это объясняет возможный класс ошибок, но не устанавливает
конкретное неверное поле потерянных ответов.

Добавлен общий output_contract из схем сервера. Схема передаётся в инструкции,
а для Timeweb/Qwen финальный запрос использует JSON Schema и видимые ID/версии
источников. Неподдерживаемый uniqueItems остаётся только в локальной проверке.
При явном отказе json_schema и при изображениях предусмотрен JSON Object.
Причина отказа сохраняется с путём поля и видна в истории. Полный ответ модели
и текст рассуждений в диагностику не записываются. Первую неправильную JSON-карту
можно исправить только один раз. Обхода согласования и проверок сцены нет.

75 тестов прошли без пропусков, ASSISTANT_LIVE_HTTP=1:
`.local-assistant-data/output-contract-tests.log`. Новые проверки включают
неполную карту, выдуманный источник, два отказа, приватность диагностики,
300 старых источников, схему запроса, явный отказ формата и изображения.
node --check и diff прошли. Интерфейс причины отказа осмотрен на синтетическом
стенде, а не в настоящем слайсере. Исправление схемы ещё не установлено в приложение.
