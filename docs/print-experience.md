# Опыт обычных печатей

В чате есть действие **«Сообщить о результате печати»**. В меню над аналитикой —
**«Опыт печати»**, небольшой просмотр последних 100 печатей и выводов.

## Сценарий

1. Рассчитайте и экспортируйте обычную деталь. Напечатайте её вручную.
2. Откройте форму результата и выберите действительно использованный расчёт.
   Принтер, материал, сопло, режим, геометрия и эффективные параметры берутся
   из снимка при запуске расчёта, а не из текущего состояния слайсера.
3. Укажите «Дефектов нет», «Есть дефекты», «Не проверялось» или «Не могу определить».
   В последнем случае нужны фотографии общего вида, сбоку и снизу. Можно добавить
   свободное описание, измерения в мм и фотографии. Пустое измерение остаётся неизвестным.
4. При дефектах выберите область и несколько проблем. Все 18 пунктов сразу не показываются.
   После сохранения выберите один дефект и соответствующий наблюдаемый признак.
   Гипотезы основаны на `kalibrovka_nastroiki_printera.md`; это альтернативные проверки.
5. Проверьте внешние причины: сухость пластика, стол, подачу, засор и механику.
   Предложение показывает один параметр, исходное и пробное значения и объяснение.
   Для применения отметьте явное согласие. Недоступная настройка, неизвестные
   диапазоны материала или направление ручной регулировки требуют ручной проверки.
6. Подготовьте повторную печать отдельной кнопкой в форме. В чате появится обычный
   план: согласуйте расчёт и экспорт. Повторного подбора настроек нет; проверяется
   именно применённое изменение. Существующие ограничения задачи сохраняются.
7. После повторной печати сохраните новый результат, выберите проверяемое исправление
   и укажите «Дефект исчез», «Стало лучше», «Хуже», «Без изменений» или неизвестный результат.
   При неудаче предлагается отдельный согласованный откат, затем другая гипотеза.

Один G-code можно напечатать несколько раз: это разные записи печати. Выбор существующей
записи в форме позволяет дополнить наблюдения, сохранив прежние ответы.
Старые расчёты без снимка параметров нельзя выдавать за достоверную историю: для них
нужен новый расчёт. Обычную физическую печать плагин не запускает.

## Хранение и подтверждение

Рядом с `sessions.json`, в каталоге `print-experience`, создаётся `experience.sqlite3`.
Таблицы: `prints`, `observations`, `adjustments`, `lessons`. Формат чатов не заменяется.
Если во встроенном Python нет `sqlite3`, используется системная SQLite Windows
через `ctypes` (`winsqlite3.dll`). Отдельный Python или установка пакетов не нужны.
Фотографии копируются в каталог опыта и сохраняются после удаления исходного чата.

- Наблюдение — факт сообщения пользователя, а не доказательство причины дефекта.
- Предложение — гипотеза; даже применение настройки не подтверждает её эффективность.
- «Стало лучше» — частичная поддержка гипотезы, без автоматического переноса настройки.
- «Дефект исчез» при новой фактической печати в условиях эксперимента — подтверждённое
  пользователем исправление. Это не лабораторное подтверждение прочности детали.
- Неудачный опыт сохраняется как неподтверждённый; откат не стирает историю.

Автоматический перенос намеренно консервативен: совпадают конкретные принтер, материал,
сопло, режим, профиль, геометрия/размеры/ориентация моделей и остальные параметры.
При сопоставлении учитываются исходное и проверенное состояния: одно изменение
может также изменить вычисляемые слайсером зависимые значения. Перед применением
обычного плана применимость ссылок на опыт проверяется заново.
Неизвестное сопло не устанавливает совместимость. Другие модели и условия не получают
автоматически настройки из этого опыта. Противоречивые подтверждённые результаты не
выбираются по принципу «последний победил». Наблюдения и подтверждённые исправления
доступны LLM через `search_print_experience`; подбор по справочнику также учитывает опыт.

Для нескольких экструдеров история сохраняется, но пробное автоматическое изменение
требует отдельной ручной проверки затронутого экструдера. Ретракт, Z-offset, компенсации
с неизвестным направлением, Input Shaping и механика не регулируются универсальным рецептом.
Фотографии сохраняются и доступны для просмотра; форма не обещает автоматического
распознавания дефектов по снимку. В полном LLM-анализе они доступны как вложения чата.

Оценка уверенности и выбор специальных калибровочных моделей в этот этап не входят.
