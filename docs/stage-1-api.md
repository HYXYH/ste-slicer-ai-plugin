# Первый этап: API и состояние

Плагин: `plugin/AIAssistant`. Все обращения к STE Slicer сосредоточены в
`slicer_bridge.py`. Сервер и хранилище не импортируют Qt и могут проверяться отдельно.
Веб-интерфейс получает состояние polling-запросами каждые две секунды.

## HTTP API

Базовый адрес: `http://127.0.0.1:<port>`. Во всех API-запросах нужен заголовок
`X-Assistant-Token` с токеном текущего запуска. Допустим только собственный Origin;
Host проверяется. Токен из стартового фрагмента URL сохраняется в `sessionStorage`.

| Метод и путь | Тело / назначение |
| --- | --- |
| `GET /api/context` | Снимок актуального состояния слайсера, полученный на главном потоке Qt |
| `GET /api/sessions` | `{sessions: [{id, title, updated_at}], active_session_id}` |
| `POST /api/sessions` | JSON `{title?: string}`; создаёт и выбирает новую сессию |
| `GET /api/sessions/<sid>` | Полная сессия; внутренние пути и таблица идемпотентности скрыты |
| `PATCH /api/sessions/<sid>` | JSON `{title: string}`; переименование |
| `POST /api/sessions/<sid>/select` | Выбор сессии; без тела |
| `POST /api/sessions/<sid>/files` | Байты одного файла; `Content-Length`, `X-File-Name` с `encodeURIComponent(name)` |
| `GET /api/sessions/<sid>/files/<fid>` | Байты изображения для просмотра; требуется токен |
| `POST /api/sessions/<sid>/messages` | JSON `{request_id, text, file_ids}`; сохраняет сообщение и ставит модели в очередь |
| `GET /api/sessions/<sid>/operations/<oid>` | Состояние конкретной операции импорта |

Успех: JSON и HTTP 200/201 (просмотр изображения возвращает его байты).
Ошибка: `{error: string}` с кодом 400, 401, 403, 404, 409, 411, 413, 415 или 500.
Предел JSON-запроса — 1 МиБ, текста — 20 000 символов, названия сессии — 120 символов.

`request_id` задаёт клиент. Повтор того же сообщения с тем же ID возвращает исходные
`{message_id, operation_ids}` без повторного импорта. Другой текст или вложения с тем же
ID дают 409. ID имеет область действия одной сессии. Намеренный повтор импорта использует
новый ID сообщения. Файлы другой сессии нельзя прикрепить по ID.

## Сессия

```json
{
  "id": "uuid",
  "title": "Кронштейн",
  "created_at": "UTC ISO timestamp",
  "updated_at": "UTC ISO timestamp",
  "revision": 1,
  "messages": [],
  "files": {},
  "operations": {},
  "task": {"description": "Требования из пользовательских сообщений", "status": "draft"}
}
```

Сообщение: `id`, `role` (`user` / `system`), `created_at`, `text`, `file_ids`.
Сообщение пользователя также содержит `context` — исторический снимок настроек.
Системное сообщение о результате может содержать `operation_id`.

Вложение в `files[fid]`: `id`, `name`, `extension`, `size`, `kind` (`model` / `image`),
`created_at`, `status`, `error`, `scene_present`, `object_ids`.
На диске также хранится `path`, который не выдаётся клиенту.

Операция в `operations[oid]`: `id`, `session_id`, `file_id`, `status`, `created_at`,
`updated_at` после изменения, `error`.

Состояния файла: `saved → queued → importing → imported` либо `error`.
При перезапуске незавершённый импорт получает `interrupted`, а успешно импортированный
файл возвращается в `saved`: присутствие в новой сцене не предполагается.
При удалении объекта из текущей сцены файл тоже возвращается в `saved`.
Операции хранят историю результата, а карточки файлов отражают текущую доступность в сцене.

Состояния задачи: `draft`, `needs_model`, `needs_description`, `importing`,
`needs_attention`, `ready`. `ready` означает наличие описания и импорт всех прикреплённых
моделей; это не оценка пригодности к печати.

## Контекст

- `available`, `updated_at`, `error`.
- `printer`: `id`, `name`, `definition_id` либо `null`.
- `mode`: `id` из `printing_mode`, понятное `name` либо `null`.
- `extruders`: `id`, `position`, `active`, `material` (`id`, `name`, `type`, `brand`).
- `profile`: `name`, `quality_type`, `quality`, `custom`, `has_user_changes` либо `null`.

Материал относится к экструдеру. При недоступности настроек возвращается явная ошибка;
значения не заменяются выдуманными данными. Обновление снимка — раз в две секунды.

## Импорт и потоки

HTTP-поток сохраняет сообщение и операцию, затем передаёт её в очередь адаптера.
`QTimer` на главном потоке Qt последовательно запускает `app.readLocalFile(QUrl, True)`.
Параметр `True` повторяет встроенную команду «Открыть как модели» и обходит восстановление
настроек 3MF-проекта.

Импорт подтверждается наличием новых mesh-объектов с путём загруженного файла в сцене,
а не возвратом HTTP-запроса. Предельное ожидание — 120 секунд; тайм-аут не останавливает
штатный загрузчик, что явно сообщается пользователю. Идентификаторы объектов действуют
только в текущем процессе. Сцена общая для всех сессий, переключение чата не восстанавливает 3MF.

Ограничения проверки файлов: валидация заголовков и базовой структуры; окончательную
проверку геометрии выполняет загрузчик STE Slicer. OBJ с внешними ресурсами не принимается.
3MF не извлекается на диск; ограничены число ZIP-записей и суммарный распакованный размер.

## Подключение следующих этапов

Агент может использовать описание и сообщения сессии, её вложения и снимок контекста.
Операции адаптера следует переиспользовать из будущих MCP-инструментов; HTTP-обработчики
не должны напрямую обращаться к Qt. Для LLM позже добавится роль `assistant` и события
вызовов инструментов. Подключение LLM в первый этап не входит.
