# AI Assistant для STE Slicer

Базовый сценарий: загрузка модели, описание назначения, анализ через LLM и MCP,
уточнения, проверяемый план, согласование, применение, штатный слайсинг и экспорт.
По дополнительному поручению включён калибровочный куб 20 мм с ручной печатью,
измерениями и проверкой видимых дефектов. Физическая печать не запускается плагином.

Состояние проверки: сетевые тесты используют настоящий localhost и тестовый
адаптер слайсера. Работу новых функций внутри STE Slicer 7.10 ещё должен проверить
человек. Ограничения перечислены ниже и в [отчёте проверки](../docs/implementation-verification.md).

## Установка в Windows

Закройте STE Slicer и дважды щёлкните **`install-plugin.cmd`** в корне репозитория.
Он сам запустит PowerShell и установит плагин. После завершения окно останется
открытым, чтобы можно было прочитать результат или ошибку.

Скрипт копирует `plugin/AIAssistant` в `%APPDATA%\steslicer\7.10\plugins\AIAssistant`
и обновляет существующие файлы. Данные диалогов хранятся отдельно.
После изменения кода снова запустите `install-plugin.cmd` и откройте STE Slicer.
Запуск не зависит от текущей папки. PowerShell-скрипт находится в `tools/install-plugin.ps1`.

При запуске из терминала можно передать параметры:

```powershell
.\install-plugin.cmd -Version 7.11
.\install-plugin.cmd -ConfigDirectory "D:\STE Slicer Config\7.10"
```

Параметр `-WhatIf` показывает папку назначения без копирования.

Для установки вручную:

1. Установите выданный организаторами STE Slicer 7.10. Плагин рассчитан на API 5,
   Python 3.5 и PyQt5, входящие в его состав; отдельные пакеты устанавливать не нужно.
2. В STE Slicer откройте **Справка → Показать папку конфигурации**.
3. Создайте в ней папку `plugins`, если её нет.
4. Скопируйте **папку `AIAssistant` из этой директории** целиком в `plugins`.
   Итоговый путь обычно выглядит так:

   ```text
   %APPDATA%\steslicer\7.10\plugins\AIAssistant\plugin.json
   ```

   Не копируйте внешнюю папку `plugin` вместо `AIAssistant` и не создавайте
   дополнительный уровень `AIAssistant\AIAssistant`.
5. Перезапустите STE Slicer. Если приложение попросит разрешить загрузку стороннего
   плагина, разрешите загрузку AI Assistant.
6. Выберите принтер и откройте **Расширения → AI Assistant → Открыть AI Assistant**.
   Команда переключит главную область на вкладку **AI ASSISTANT** рядом с Prepare.
   Внешний браузер и Qt WebEngine для этого не нужны. Слева остаётся штатная
   панель настроек Prepare; файлы программы слайсера не заменяются.

Вкладка зарегистрирована через штатный механизм Stage. **«Все чаты»** открывает
список для переключения, создания, переименования и объединения задач.
Объединение создаёт новый чат с копиями переписки и вложений; исходные чаты
сохраняются. Старые планы, согласия и результаты расчёта не переносятся.
После объединения нужны новый анализ и согласование. Во время активных операций
объединение блокируется. Копирование файлов не удерживает общую блокировку истории.

**«Аналитика»** переключает содержимое той же вкладки. Возврат в Prepare
останавливает только обновление интерфейса: анализ продолжает работу, черновики
сохраняются до закрытия слайсера. История и прежние подключения остаются общими.
Вспомогательные формы открываются поверх содержимого вкладки.

При обновлении закройте STE Slicer, замените папку `AIAssistant` и запустите приложение снова.
Для удаления закройте приложение и удалите эту папку. Данные диалогов хранятся отдельно.

## Использование

- Создайте задачу кнопкой **«Новая задача»**. Сессии можно переключать и переименовывать.
- Введите назначение детали и требования. Прикрепите модель и при необходимости фото.
- После загрузки вложений нажмите **«Отправить»**. Модель будет импортирована в сцену;
  фото сохранится как вложение. Успех импорта показывается после появления модели в сцене.
- Модели: STL (ASCII/бинарный), OBJ с геометрией без внешних MTL/текстур, 3MF.
  Изображения: JPG/JPEG, PNG. Максимальный размер одного файла — **100 МиБ**,
  до 20 вложений в сообщении.
- 3MF открывается **как геометрия**, без восстановления настроек проекта.
- Принтер, режим, материалы экструдеров и профиль обновляются примерно раз в две секунды.
  Отсутствующие значения и ошибки отображаются явно.
- `Ctrl+Enter` отправляет сообщение. Вложения можно перетащить в окно.
  Двойное нажатие на ожидающее вложение убирает его из сообщения.

**Сцена слайсера общая для всех чатов.** Переключение сессии восстанавливает переписку,
но не меняет сцену и настройки. Новая задача также не очищает сцену.
После перезапуска история остаётся, а модели автоматически не импортируются повторно.
Для повторного импорта используйте кнопку **«Загрузить в сцену»** у вложения.
Если модель удалена из сцены, её карточка снова показывает «Сохранён».

## Подключение LLM и подготовка G-code

1. Откройте **«Подключение LLM»** в левой панели.
2. Введите Base URL организаторов, выбранную модель и API key.
3. Нажмите **«Сохранить»**, затем **«Проверить подключение»**.
   Пустое поле ключа сохраняет прежний ключ. Удаление выполняет отдельная кнопка.
   Статус «Ключ сохранён в STE Slicer» подтверждает сохранение. Поле после
   сохранения очищается, чтобы секрет не оставался в форме; это не удаление.
4. Прикрепите модель, опишите назначение и отправьте сообщение.
   Если описание уже сохранено, нажмите **«Повторить анализ»**.
   По умолчанию включён пошаговый анализ: подтвердите понимание требований,
   затем материал. Согласие с материалом разрешает его выбор в слайсере;
   непроверенные свойства детали объясняются в ограничениях рекомендации.
   Расчёт требует согласования карточки плана, без подтверждения испытаний и принятия риска.
   В «Подключение LLM» можно выбрать прежний анализ полной карты одним запросом.
5. Ответьте на вопросы. Для чисел укажите единицы. Ответ «Не знаю» сохраняет
   неопределённость, но позволяет продолжить подбор по доступным данным.
   Допущения показаны как пояснения; исправить их можно сообщением в чат.
6. Проверьте карточку: материал, режим, профиль, каждое изменение и ограничения.
   Нажмите **«Согласовать, применить и рассчитать»**.
7. Дождитесь завершения штатного backend. Время показано в секундах,
   длина материала — в метрах, в исходных единицах PrintInformation.
8. Нажмите **«Выбрать папку и сохранить»**. Qt откроет диалог папки.
   В ней появятся `project.3mf` и `result.gcode`. Замена существующих файлов
   разрешается только отдельным флажком перед выбором папки.
   Оба штатных экспортёра работают через фоновый WriteFileJob; интерфейс не ждёт
   их завершения в главном потоке. Ошибка или изменение сцены запрещают публикацию
   временного файла. Уже существующий проект сохраняется при неудачной записи.
9. Проверьте предпросмотр G-code. Откройте 3MF в отдельной проверочной сцене.

Анализ показывает «Известно», вопросы, ограничения и раскрываемую историю
инструментов. Кнопка остановки запрещает дальнейший анализ. Поздний ответ LLM
не возобновляет отменённый запуск. Она не обещает остановить штатный импорт
или уже запущенный backend.

Один ответ LLM ожидается до 120 секунд, весь анализ — до 360 секунд.
Для Timeweb с моделью `dashscope/qwen3.8-flash` отключено thinking и ограничен
вывод до 8192 токенов. Корректная карта из первого ответа не требует второй
генерации. Поддержку расширений шлюзом подтверждает полный анализ, а не
короткая проверка подключения. Другим провайдерам эти параметры не отправляются.

Точная схема карты передаётся вместе с инструкцией. Для Timeweb/Qwen финальный
ответ запрашивается в JSON Schema; локальные проверки остаются обязательными.
Если карта отклонена, раскройте «Действия текущего запуска» → «Проверка ответа LLM»:
там показаны поле и причина. Полные ответы и текст рассуждений в диагностику
не записываются. Неправильную JSON-карту можно исправить только один раз.

Если профиль для выбранной комбинации режима и материала пока не подтверждён,
анализ сохраняет неполный вариант и показывает ограничение. План недоступен,
пока профиль не подтверждён. В режиме полной карты ответ о желаемом материале
или режиме в чате не меняет настройки STE Slicer. Пошаговый режим выбирает
материал после отдельного согласия. Если целевая конфигурация всё ещё недоступна,
выберите её в приложении и повторите анализ.

Ручное изменение геометрии, положения, настроек или состава сцены делает
план и результат устаревшими. Новое требование также требует нового анализа.
Другие модели нужно явно включить в задачу либо убрать из сцены.

## Аналитика подготовки

Откройте **«Аналитика»** в левой панели. Доступны периоды 7/30 дней и всё время,
сводка задач, график запусков, текущие препятствия, метрики LLM и инструментов,
оценки времени/материала и CSV. По названию задачи можно вернуться в её чат.
Поиск и фильтры применяются к таблице; CSV содержит все задачи выбранного периода.
Черновик сообщения сохраняется при переключении. Обновление — раз в 10 секунд
при открытом дашборде или вручную. Вызовов LLM и изменений слайсера для аналитики нет.

Токены показываются только по `usage` API с указанием полноты данных. Оценки
печати учитывают последний актуальный расчёт, без суммирования повторных проб.
Устаревшие результаты исключены; сохранённые 3MF + G-code считаются отдельно.
Это не измерение прочности, себестоимости или качества изготовленной детали.
Подробные определения и ограничения: [аналитика](../docs/analytics.md).

### Ограничения текущей реализации

- Предварительная проверка каталогов и зависимостей выполняется для текущего
  режима и материала. Проверка другой конфигурации возвращает
  `TARGET_CONFIGURATION_UNKNOWN`. Пошаговый режим может выбрать материал
  после согласия пользователя и заново прочитать фактическую конфигурацию.
  При таком ответе выберите режим и материал в STE Slicer и повторите анализ.
- Инструменты смены режима и материала реализованы, но план, для которого
  нельзя заранее подтвердить целевую совместимость, не получает разрешение.
- Источники семи выданных задач сохранены как `observation`. Проверенных
  инженерных рецептов нет. Описания задач не подтверждают прочность материала.
- Непроверенные свойства детали остаются ограничениями рекомендации и плана,
  без запроса инженерных проверок и принятия риска. Подбор материала и настроек
  не подтверждает свойства готовой детали и не отменяет совместимость профиля.
  Нельзя считать геометрию без поддержек проверенной по одним габаритам.
- Созданный пользовательский профиль получает реальный ID после создания.
  Выбор этой новой копии в другом плане требует повторного чтения каталога.
- Библиотеки и реальные API 7.10, лицензия 5D, все обязательные группы
  инструментов и итоговые комплекты по моделям ещё требуют проверки в приложении.
  API организаторов без введённого ключа не проверен.
- Физическая печать не запускается. Куб подготавливается отдельным планом
  с согласованием; измерения и оценку дефектов вводит человек.

## Техническое задание из Word

В чат можно прикрепить `.docx` вместе с моделью или отдельным сообщением.
Абзацы и таблицы извлекаются локально и передаются модели как данные задачи
в обоих режимах анализа. У требований сохраняются ссылки на файл-источник.
Кнопка «Текст извлечён · Посмотреть» открывает извлечённый текст.
Старый `.doc` нужно предварительно сохранить в `.docx`. Сканы без текстового
слоя не распознаются. Макросы и инструкции внутри документа не исполняются.
Ограничения: 30 000 символов на документ, 120 000 символов на текст задачи
и документов в чате, 4 МиБ на XML текста документа. Превышение лимита или
ошибка чтения показываются явно; содержимое не обрезается незаметно.

## Названия и список чатов

Чат с названием «Новая задача» автоматически получает короткое название по
распознанному назначению детали и дату/время создания. Отдельный запрос к LLM
для названия не выполняется. Названия, отредактированные пользователем, сохраняются.
«Все чаты» открывает отдельный вид с поиском, прокруткой и датами изменений.
Кнопка «Редактировать» рядом с названием позволяет изменить его прямо в строке.
Удаление требует подтверждения и удаляет переписку и вложения только этого чата;
сцена и экспортированные файлы сохраняются. Чат с активной операцией удалить нельзя.
После удаления текущего чата остаётся список. Кнопка «Назад» в левом меню возвращает
в предыдущий доступный чат. Выбранные чаты можно объединить в новый, как и раньше.

## Вид аналитики

В аналитике верхняя панель периода, поиска, фильтра, обновления и экспорта CSV
остаётся неподвижной. Основная область прокручивается целиком: четыре карточки
итогов, активность по дням, предупреждения, использование LLM, инструменты и задачи.
На узкой ширине итоговые карточки располагаются в два ряда.
Нажатие на предупреждение показывает связанные задачи в таблице ниже; выбранную
проблему можно сбросить. Название задачи открывает её чат. Отсутствующие оценки
обозначаются «Нет данных», для медианы и p95 доступны пояснения при наведении.
Расчёты отчёта и экспорт CSV используют прежние данные и выбранный период.

## Шапка и действия анализа

Название текущего чата отображается по центру. Карандаш открывает редактирование:
Enter сохраняет название, Escape отменяет. Ниже показаны статус и дата изменения.
Постоянные верхние кнопки повторного анализа и перехода к готовности данных убраны.
В чате показывается действие по текущему состоянию: настройка LLM, повтор после
ошибки, новый запуск после прерывания или обновление устаревшего анализа.
Во время анализа доступна остановка. При ожидании ответов повторный запуск
не предлагается. «Подготовить план куба» находится в карточке параметров калибровки.
После перезапуска вместо технического ограничения показано уведомление с кнопкой
«Обновить анализ». История остаётся сохранённой. Поле ввода длинных сообщений
поддерживает вертикальную прокрутку и показывает полосу прокрутки при переполнении.

## Карточка готовности данных

Число из 100 показывает **полноту необходимых данных для подбора параметров**,
а не вероятность успешной печати или эксплуатационную пригодность детали.
Карточка находится первой справа и содержит три компонента с прогрессбарами.

| Компонент | Баллы | Что учитывается |
| --- | --- | --- |
| Модель и размеры | 30 | Наличие целевых моделей: 10; габариты всех целевых моделей прочитаны: 20 |
| Материал и профиль | 30 | Принтер и режим: по 5; материал и подтверждённый совместимый текущий профиль: по 10 |
| Задача и условия эксплуатации | 40 | Назначение, нагрузка, рабочая температура, среда; точность и поверхность — если существенны для задачи |

Условия учитываются по общей карте требований, которую использует анализ.
Ответы в чате, ТЗ и кнопки «Уточнить» обновляют одни данные. После обработки
сообщения карточка пересчитывается; отдельно вводить тот же ответ не требуется.
Ответ «не знаю» не засчитывается; явное «не применяется» засчитывается.
Противоречивое значение не даёт баллы до уточнения. Указаны источники сведений.
Порог удалён. Измерения куба не влияют на полноту данных: 100 достижимо без куба.

Действия агента показаны сворачиваемыми группами между сообщениями чата.
Начало и завершение команды объединены; раскрываются аргументы, результат,
статус и длительность. Полные события доступны через «Подробности команды».
Согласие с материалом подтверждает только его выбор. Подтверждать испытания
и принимать риск для подготовки печати не требуется.

Результат распознавания ТЗ отображается в переписке карточкой «Распознаны
требования». Сразу видны до пяти основных характеристик; остальные раскрываются.
Противоречивые и неизвестные значения остаются видимыми в свёрнутом виде.
Карточка сохраняет снимок требований на момент ответа, а раскрытие не запускает
анализ повторно. Технические ключи заменены понятными подписями; исходные поля
и ссылки на источники доступны в подробностях. Подтверждение требований осталось
в существующем сценарии вопросов.

## Калибровочный куб

Для обычных печатей добавлены **«Сообщить о результате печати»** в чате и
**«Опыт печати»** над аналитикой в меню. Локальная SQLite-база хранится отдельно
от чатов: наблюдения, фотографии, гипотезы, одно согласованное изменение и результат
повторной печати. [Сценарий и ограничения](../docs/print-experience.md).

В карточке предлагаемых параметров явно показаны нехватка или противоречия
данных. Там же доступна кнопка «Провести калибровку». Для неё нужны выбранные
принтер, материал и совместимый профиль. Куб проверяет размеры и видимые
дефекты печати, но не заменяет уточнение ТЗ или проверку прочности детали.
Номинал — 20 мм, допуск — ±0,2 мм. Неуспешные измерения остаются предупреждением
независимо от числа баллов в карточке «Данные».

1. Нажмите **«Провести калибровку»**. Создастся отдельный чат со встроенной STL.
2. Сохраните основной проект, очистите сцену в Prepare и загрузите куб из чата.
3. Нажмите **«Подготовить план куба»**. План сохраняет текущие параметры;
   повторного подбора моделью нет. Затем согласуйте расчёт и сохраните 3MF/G-code.
4. Напечатайте куб вручную. Отметьте X/Y до снятия со стола, Z — высота.
5. Нажмите **«Ввести измерения куба»**, заполните X/Y/Z и проверки дефектов,
   подтвердите фактическую печать. Числа сами по себе не доказывают качество.
6. Вернитесь к исходной детали, восстановите модель и ту же конфигурацию.

Измерения привязаны к хешу принтера, материала, профиля и всех эффективных
глобальных/экструдерных настроек. При их изменении прежний куб не даёт баллы.
Полнота данных не заменяет согласование плана, проверку свежести сцены, совместимость,
контроль результата штатного backend или инженерные испытания.
Проверка G-code подтверждает актуальность результата для снимка входной сцены;
полное геометрическое сравнение траекторий с исходной моделью не выполняется.

## Данные и доступ

Данные находятся в `ai_assistant` внутри каталога данных STE Slicer
(`UM.Resources.getDataStoragePath()`; на Windows обычно та же папка версии,
которую открывает меню конфигурации):

```text
ai_assistant/
├── sessions.json
├── sessions.json.v1.bak  # резервная копия при первом переходе с формата v1
└── uploads/<session_id>/<file_id>.<extension>
```

История и файлы остаются на компьютере. Не удаляйте и не редактируйте `sessions.json`
при работающем плагине. Для резервной копии закройте STE Slicer и скопируйте всю
папку `ai_assistant`.

Карта задачи, запуски, события и планы хранятся в `sessions.json` версии 2.
Миграция сохраняет старые сообщения, файлы, операции и таблицу повторов.
Повреждённая история не заменяется пустой. После перезапуска незавершённые
операции получают `interrupted`, планы — `stale`.

Ключ LLM хранится через Preferences STE Slicer в `ai_assistant/api_key`.
Он не шифруется отдельным хранилищем ОС. GET настроек выдаёт только
`base_url`, `model`, `pipeline` и `key_configured`. История и события не содержат ключ.
При анализе текст и выбранные изображения отправляются на указанный Base URL;
геометрия передаётся как результаты инструментов, без бинарных дампов STL.
Перенаправления LLM HTTP-запросов запрещены; проверка TLS остаётся включённой.

Сервер слушает только `127.0.0.1`; порт выбирается ОС. Доступ к API защищён
случайным токеном запуска. Нативное окно передаёт его только заголовком локальных
запросов; прокси и перенаправления этих запросов отключены. Текст задачи отображается
без исполнения HTML и загрузки внешних ресурсов. Для браузерного стенда разработки
сохранён вход по фрагменту URL и `sessionStorage`. После перезапуска слайсера
откройте окно через меню снова.

## Если что-то не работает

- **Нет пункта меню:** проверьте расположение `plugin.json`, версию API и перезапуск.
- **Окно не открывается:** перезапустите STE Slicer после установки и проверьте журнал.
- **Нет локального подключения:** закройте окно ассистента и откройте его через меню снова.
- **Не выбран принтер:** сначала выберите его в STE Slicer, затем повторите импорт.
- **Ошибка формата:** проверьте, что файл действительно содержит модель соответствующего
  формата; расширение и базовая проверка не гарантируют, что штатный загрузчик его прочитает.
- **Импорт не завершён за 120 секунд:** проверьте сообщения и сцену слайсера. Его загрузчик
  может ещё работать; убедитесь, что модель не появилась, прежде чем повторять импорт.
- **Ошибка запуска или контекста:** смотрите `steslicer.log`, `stderr.log` или другие `*.log`
  в папке конфигурации. Сообщения плагина содержат `AIAssistant` / `AI Assistant`.

## Разработка и проверки

Все Python-скрипты разработки и тесты используют одну `.venv` в корне репозитория.
Если она уже существует, переиспользуйте её. При первом запуске создайте среду
(системный Python используется только для этой команды):

```powershell
py -3 -m venv .venv
```

Затем из корня репозитория установите зависимости и запускайте команды через
явный путь к интерпретатору среды. Активировать её в PowerShell необязательно:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check plugin/AIAssistant/web/app.js
.\.venv\Scripts\python.exe tools/dev_server.py
```

Сейчас `requirements.txt` содержит только пояснения: сервер и тесты используют
стандартную библиотеку. При добавлении внешних зависимостей указывайте их в этом
файле. `.venv` исключена из Git. PyQt5, UM и steslicer предоставляет установленный
STE Slicer; рабочий плагин использует его встроенный Python 3.5.

Для тестов отдельного окна установите `requirements-dev.txt` в ту же `.venv`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:QT_QPA_PLATFORM = 'offscreen'
$env:ASSISTANT_LIVE_HTTP = '1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_native_window.py -v
```

Qt-тесты выполняются без видимых окон и без запуска STE Slicer. Они используют
локальный тестовый провайдер и адаптер слайсера. PyQt5 5.15 в среде разработки
не подтверждает работу внутри штатного Qt 5.10; окончательную проверку выполняет человек.
Без этих необязательных зависимостей тесты Qt Widgets и Qt Quick пропускаются.
Встроенная вкладка проверяется файлом `test_assistant_tab.py`; объединение,
скор и калибровочные записи — `test_workspace.py`.

Последняя команда выводит локальную ссылку для разработки интерфейса.
Откройте её целиком. Сервер использует настоящее хранение сессий и вложений в
`.local-assistant-data`, но явно сообщает, что слайсер не подключён, и не имитирует
успешный импорт. Остановка — `Ctrl+C`.

План реализации, состояние работ и описание API: [план базового сценария](../docs/draft-implementation-plan.md).

По умолчанию тесты прогоняют настоящий HTTP-обработчик через потоки в памяти,
без сетевого соединения. Для проверки через TCP в среде с разрешённым localhost:

```powershell
$env:ASSISTANT_LIVE_HTTP = '1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Remove-Item Env:ASSISTANT_LIVE_HTTP
```

Проверка P00 от 2026-10-24: в общей `.venv` на Python 3.13 прошли 11 тестов в памяти;
ещё один тест требует `ASSISTANT_LIVE_HTTP=1`. Через настоящий localhost прошли все 12 тестов
и 20 повторов проверки отклонённых загрузок. В песочнице доступ к localhost заблокирован;
TCP-проверки выполнены вне песочницы. JavaScript прошёл `node --check`, исходники плагина
проверены на синтаксис Python 3.5. Исправлено закрытие соединения после отклонения загрузки:
сервер отправляет ответ и ограниченно дочитывает входящие данные (до 1 МиБ, до 1 секунды),
чтобы непрочитанное тело запроса не сбрасывало соединение до получения JSON ошибки.

Установка в отдельную проверочную папку прошла; хеши всех 10 файлов совпали с исходниками.
